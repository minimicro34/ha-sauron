# Contributing to SAURon

Thank you for your interest in contributing to **SAURon**.

Contributions are welcome, including bug fixes, new features, documentation improvements, translations, and tests.

---

## Development environment

Clone the repository and install the development dependencies:

```bash
git clone https://github.com/minimicro34/ha-sauron.git
cd ha-sauron

python -m pip install --upgrade pip
python -m pip install -e . pytest pytest-asyncio pytest-cov ruff
```

The project CI currently runs on Python 3.14.

---

## Development workflow

Create a dedicated branch for your changes:

```bash
git switch main
git pull
git switch -c feature/my-change
```

Format the code when needed:

```bash
make format
```

Run the complete local validation before committing:

```bash
make check
```

`make check` runs the same Python quality checks used by the GitHub Actions workflow:

- Python bytecode compilation
- Ruff lint
- pytest with coverage

Additional Makefile targets are available:

```bash
make compile
make format
make format-check
make lint
make test
make clean
```

Hassfest and HACS validation remain part of GitHub Actions.

---

## Tests

Please add or update tests whenever a functional change is introduced.

Run the complete test suite with coverage:

```bash
make test
```

The configured coverage threshold must remain satisfied.

---

## Translations

When adding or changing user-facing strings:

- update `custom_components/sauron/strings.json`;
- update the corresponding files in `custom_components/sauron/translations/`;
- keep translation keys synchronized between languages;
- do not remove existing translation keys without checking their usage.

Run the project validation checks before committing translation changes.

---

## Pull requests

Before opening a Pull Request:

- keep the PR focused on a single logical change;
- update your branch from the latest `main`;
- run `make format` when code formatting changed;
- run `make check`;
- update `CHANGELOG.md` for user-visible changes;
- update the README or other documentation when appropriate.

Please describe:

- what changed;
- why the change was needed;
- how it was tested;
- any compatibility considerations.

---

## Commit messages

Use short, descriptive commit messages written in the imperative mood.

Examples:

```text
Handle delayed daily consumption
Add estimated index retry tests
Update water dashboard example
Improve SAUR API error handling
```

---

## Reporting issues

When reporting a bug, please include:

- Home Assistant version;
- SAURon version;
- installation method (HACS or manual);
- relevant logs;
- diagnostics generated by Home Assistant when available;
- steps to reproduce the issue.

Please remove or anonymize sensitive information before publishing logs or diagnostics.

---

## Security and privacy

Never publish:

- SAUR account credentials;
- authentication tokens, cookies, or session identifiers;
- private API data that can identify an account or contract;
- any other private authentication information.

---

## Code style

This project follows Home Assistant development conventions whenever applicable.

Please refer to:

https://developers.home-assistant.io/

Contributions should:

- pass `make check`;
- include tests when appropriate;
- keep translations synchronized;
- follow the existing project style.
