# Contributing to SAURon

Thank you for your interest in contributing to **SAURon**.

Contributions are welcome, including bug fixes, new features, documentation improvements, translations, and tests.

---

## Development environment

Clone the repository and install the development dependencies:

```bash
git clone https://github.com/minimicro34/ha-sauron.git
cd ha-sauron

python3 -m venv .venv-sauron
source .venv-sauron/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements-dev.txt
python -m pip install -e .
```

The project CI currently runs on Python 3.14. Use an isolated virtual environment for local tests so a globally installed Home Assistant does not interfere with Recorder mocks. The editable install supplies runtime dependencies (including Voluptuous), while `requirements-dev.txt` lists development tools and direct test imports.

## Development workflow

Create a dedicated branch for your changes:

```bash
git switch main
git pull
git switch -c feature/my-change
```

Format the code when needed:

```bash
make fix
```

`make fix` formats the repository and applies Ruff's automatic lint fixes. Use `make format` when only formatting is needed. Review the resulting diff before committing.

Run the complete local validation before committing:

```bash
make check
```

`make check` runs the same Python quality checks used by the GitHub Actions workflow:

- Python bytecode compilation
- Ruff lint
- pytest with coverage

Additional Makefile targets are available:

```bash
make compile
make format
make format-check
make fix
make lint
make test
make clean
```

The bundled Lovelace card also has JavaScript syntax and regression checks:

```bash
node --check custom_components/sauron/www/sauron-card.js
node --test tests/js/sauron-card.test.cjs
```

Run these checks when changing the card or its visual editor. They complement `make check`, which covers Python quality and tests.

Hassfest and HACS validation remain part of GitHub Actions.

## Tests

Please add or update tests whenever a functional change is introduced.

Run the complete test suite with coverage:

```bash
make test
```

The project enforces a **minimum global test coverage of 90%**. `make test`, `make check`, and the Python quality CI job fail if coverage drops below that threshold.

New or changed behavior should be covered by meaningful tests. Do not add tests solely to satisfy the percentage: prefer exercising functional paths, error handling, recovery behavior, and relevant edge cases.

The current coverage may be higher than the enforced minimum; contributors should preserve or improve useful coverage whenever practical.

## Recorder historical statistics

SAURon publishes dated daily water statistics automatically through Home Assistant Recorder. Historical backfills and cumulative baseline repairs are separate, guarded maintenance actions; they are not ordinary polling operations.

Before changing the historical importer, cover partial or interrupted Recorder writes, duplicate verification and corrections, missing or malformed daily rows, timezone boundaries, restart persistence, and publication resumption. A queued write is **not** proof of completion: use the read-only verification action and retain the pending marker until Recorder rows are verified. Never repeat a queued import blindly.

The positive first-import path has automated Recorder regression coverage, but still requires validation against a fresh real Recorder database. Keep statistic IDs and existing cumulative offsets compatible across upgrades.

## Translations

When adding or changing user-facing strings:

- update `custom_components/sauron/strings.json`;
- update the corresponding files in `custom_components/sauron/translations/`;
- keep translation keys synchronized between languages;
- do not remove existing translation keys without checking their usage.

Run the project validation checks before committing translation changes.

---

## Pull requests

Before opening a Pull Request:

- keep the PR focused on a single logical change;
- update your branch from the latest `main`;
- run `make format` when code formatting changed;
- run `make check`;
- keep global test coverage at or above **90%**;
- update `CHANGELOG.md` for user-visible changes;
- update the README or other documentation when appropriate.

Please describe:

- what changed;
- why the change was needed;
- how it was tested;
- any compatibility considerations.

---

## Commit messages

Use short, descriptive commit messages written in the imperative mood.

Examples:

```text
Handle delayed daily consumption
Add estimated index retry tests
Update water dashboard example
Improve SAUR API error handling
```

---

## Reporting issues

When reporting a bug, please include:

- Home Assistant version;
- SAURon version;
- installation method (HACS or manual);
- relevant logs;
- diagnostics generated by Home Assistant when available;
- steps to reproduce the issue.

Please remove or anonymize sensitive information before publishing logs or diagnostics.

---

## Security and privacy

Never publish:

- SAUR account credentials;
- authentication tokens, cookies, or session identifiers;
- private API data that can identify an account or contract;
- any other private authentication information.

---

## Code style

This project follows Home Assistant development conventions whenever applicable.

Please refer to:

https://developers.home-assistant.io/

Contributions should:

- pass `make check`;
- keep global test coverage at or above **90%**;
- include tests when appropriate;
- keep translations synchronized;
- follow the existing project style.
